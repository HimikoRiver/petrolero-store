# Шаг 1. Локальная PostgreSQL и авторизация Petrolero

Рабочая ветка: `feature/storefront-catalog`. Интернет, домен, оплаченный сервер и публичная база **не нужны**. Нужны установленные **Node.js 22** и **Docker Desktop** (с запущенным Docker Engine).

## Что уже реализовано

- Better Auth с регистрацией, обязательным подтверждением почты, входом, выходом, сессиями и сбросом пароля.
- Prisma 7, PostgreSQL и SQL-миграции, включая настройку двухфакторной авторизации.
- Личный кабинет и защита приватных маршрутов.
- Роли покупателей и администраторов (не назначайте ADMIN до подтверждения почты).
- Проверки API и полного auth-flow в GitHub Actions с временной БД и Mailpit.

Этот этап добавляет воспроизводимый **локальный запуск**, не заменяя существующие формы, страницы и демотовары.

## Первый запуск (Windows CMD)

Открой CMD в корне `petrolero-store` и выполни по порядку:

```cmd
git pull --ff-only origin feature/storefront-catalog
npm ci
npm run local:setup
npm run local:up
npm run local:db:deploy
npm run local:check
npm run dev
```

Если Docker Desktop ещё не установлен, установи его и дождись запуска Docker Engine **до** `npm run local:up`. При первом запуске Docker скачает образы.

Проверка:
- Сайт: http://localhost:3000/
- Регистрация и вход: http://localhost:3000/account/login
- Тестовый почтовый ящик: http://127.0.0.1:8025
- База данных: PostgreSQL на `127.0.0.1:55432`, имя `petrolero_dev`.

При регистрации укажи тестовую почту и придумай пароль длиной минимум 10 символов. Письмо попадёт **только** в локальный Mailpit; реальных писем в интернет не отправляется. Открой письмо в Mailpit, нажми ссылку подтверждения и войди в аккаунт. Затем проверь `/account`. Сброс пароля можно проверить там же через кнопку «Забыли пароль?».

## Безопасность и сохранение данных

- `compose.local.yml` привязывает PostgreSQL, SMTP и Mailpit UI **только к 127.0.0.1**, а не к публичной сети.
- `npm run local:setup` генерирует случайные пароли БД/SMTP и Better Auth secret в локальном `.env.local`, который игнорируется Git.
- При существующем `.env.local` сценарий сохраняет его резервную копию `.env.local.backup-...` и бережно обновляет только ключи локального backend. Если `DATABASE_URL` указывает на другую БД, обновление останавливается. Для намеренной смены источника есть `npm run local:setup -- --switch`. Проверь последствия, прежде чем применять `--switch`.
- `npm run local:db:deploy` выполняет миграции **только** в `127.0.0.1:55432/petrolero_dev`; для чужой или удалённой БД он завершится ошибкой.
- `CATALOG_SOURCE=demo`: текущая витрина сохраняется. Демотовары не импортируются в новую БД.
- Данные PostgreSQL и письма Mailpit хранятся в Docker volumes. `npm run local:down` останавливает сервисы, **не удаляя** данные. Не запускай `docker compose down -v` без намерения удалить тестовую БД.
- Настройки Mailpit с приёмом любого пароля допустимы **только в локальном тестовом окружении** и не должны использоваться на публичном сервере.

## Повторный запуск

```cmd
npm run local:up
npm run local:check
npm run dev
```

После изменений схемы повторно выполни `npm run local:db:deploy`. Для просмотра таблиц можно запустить `npm run db:studio`.

Для остановки Docker-сервисов:

```cmd
npm run local:down
```

## Двухфакторная защита (TOTP)

В разделе [Безопасность аккаунта](http://localhost:3000/account/security) пользователь может включить второй фактор. Приложение-аутентификатор (Google Authenticator, Microsoft Authenticator и др.) сканирует QR-код, который формируется **локально в браузере**. Ключ TOTP не передаётся внешним QR-сервисам.

1. Откройте `/account/security` из авторизованного аккаунта.
2. Введите действующий пароль, отсканируйте QR-код и подтвердите шестизначный код из приложения.
3. **Обязательно сохраните резервные коды** вне телефона. Они показываются после подтверждения; повторно автоматически не отображаются.
4. При следующем входе после пароля система запросит TOTP-код или одноразовый резервный код. До его подтверждения сессия не создаётся.
5. Для отключения 2FA или перевыпуска резервных кодов нужен действующий пароль; после перевыпуска старые коды недействительны.

Перед запуском обновлённого проекта примените новую миграцию и сгенерируйте Prisma Client, **не удаляя существующий Docker volume**:

```cmd
git pull --ff-only origin feature/storefront-catalog
npm run local:db:deploy
npm run db:generate
npm run dev
```

Остановите текущий `npm run dev` перед выполнением команд и запустите его снова после генерации. Существующие аккаунты продолжают работать с одним паролем до самостоятельного включения 2FA. **Не меняйте `BETTER_AUTH_SECRET` после подключения 2FA:** он нужен для расшифровки TOTP-секретов и резервных кодов.

## Если что-то не запускается

- **Команда docker не найдена:** установи Docker Desktop или запусти его.
- **Порт 55432, 1025 или 8025 занят:** останови конфликтующий процесс; настройки проброса портов и `.env.local` должны оставаться согласованными.
- **PostgreSQL не подключается:** проверь `docker compose --env-file .env.local -f compose.local.yml ps`.
- **Миграции не применяются:** проверь `npm run local:check` и сообщения `npm run local:db:deploy`. Если раньше существовал volume с другим паролем, **не удаляй данные без резервной копии**.
- **Регистрация возвращает 503:** проверь `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, Docker и `npm run local:check`; перезапусти Next.js после изменения `.env.local`.
- **Письмо не пришло в Mailpit:** SMTP должен работать на `127.0.0.1:1025`; проверь вкладку Mailpit и вывод dev-сервера.

## Границы этого этапа

GitHub хранит код и инструкции, но не управляет Docker Desktop на твоём компьютере. Поэтому подключение к **фактически запущенной** локальной PostgreSQL подтверждается только выводом `npm run local:check` на твоём ПК. До такого подтверждения нельзя утверждать, что БД уже запущена и регистрация реально прошла.

Тест `scripts/check-auth-flow.mjs` предназначен для **отдельной временной базы CI**: он создаёт и изменяет тестовые данные. Не запускай его на своей рабочей локальной базе без специальной тестовой изоляции.

Следующий отдельный этап — назначение ADMIN и проверка всех административных операций. Это не требует публикации сайта, но должно выполняться после успешного входа.
