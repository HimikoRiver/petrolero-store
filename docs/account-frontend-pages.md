# Petrolero — страницы покупателя, UI-этап

Ветка: `feature/storefront-catalog`.

## Готовые пути

### Личный кабинет (требуют настоящей сессии Better Auth)
- `/account` — обзор.
- `/account/orders` — история заказов.
- `/account/orders/[orderId]` — защищённый маршрут подробностей; пока без заказов.
- `/account/favorites` — избранные товары из текущего каталога (временно localStorage).
- `/account/addresses` — адреса и получатели.
- `/account/profile` — персональные данные.
- `/account/settings` — рассылки и уведомления.
- `/account/security` — безопасность.
- `/account/support` — помощь покупателю.
- `/account/returns` — возвраты.

### Публичный предпросмотр без регистрации
- `/account/preview` — обзор.
- `/account/preview?section=orders` — заказы, и т. д.

Этот предпросмотр не эмулирует вход, не показывает чужих пользователей и не записывает персональные данные. Для разработки позволяет увидеть все страницы без PostgreSQL/SMTP.

### Справка
- `/help/delivery-payment`
- `/help/warranty-returns`
- `/help/faq`

Справочные тексты предварительные: юридические сроки и способы доставки необходимо подтвердить у заказчика до публикации.

## Важные решения
- Страница `/account/login`, её видеозаставка и стили не изменены.
- Кабинет оформлен в одном тёмном графитовом стиле, адаптирован для телефонных, планшетных и настольных экранов.
- Маршрут `/account/orders/[orderId]` в будущем должен делать запрос `WHERE userId = session.user.id AND id = orderId`. Пока он только показывает состояние без данных, ничего не раскрывает.
- Для неавторизованного посетителя приватные пути перенаправляют на `/account/login?next=...`, если инфраструктура подключена.
- При отсутствии настроенной БД приватные страницы показывают ссылку на безопасный UI-предпросмотр.
- Форма входа пока не подключена к auth-client; не выдавать регистрацию за рабочую.
- Профиль, адреса, заказы, уведомления, возвраты и поддержка ещё не связаны с серверными моделями. Не показывать фальшивые записи и не имитировать сохранение.

## Следующий технический этап
Подключить актуальную видео-форму к Better Auth, запустить PostgreSQL и SMTP; затем реализовать модели Profile/Address/Order и настоящие CRUD-операции. Сторонние сервисы и продакшен-домен не нужны для итерации над интерфейсом.
