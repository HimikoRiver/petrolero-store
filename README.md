# Petrolero Store

Интернет-магазин моторных масел Petrolero. Next.js 16 (App Router), React 19, TypeScript и Tailwind CSS 4.

## Запуск

```cmd
npm ci
npm run dev
```

Главная: http://localhost:3000/

Сохранённые самостоятельные экраны:
- http://localhost:3000/menu-demo — карточки меню.
- http://localhost:3000/molecules-demo — молекулы и бутылочки.

## Архитектура

- `src/app/` — исключительно роуты и корневой layout.
- `src/features/home/` — композиция главной страницы.
- `src/features/home/hero/` — первый экран, видео и WebGL-волны.
- `src/features/home/header/` — закреплённая шапка, логотип и поиск.
- `src/features/home/story/` — скролл-текст, анимация логотипа и переключение на сцену преимуществ.
- `src/features/home/advantages/` — семь карточек преимуществ, их данные и стили.
- `src/features/home/technology/` — четвёртый экран: три временные карточки транспорта, видео двигателя, подписи и точки, появляющиеся по времени воспроизведения.
- `src/features/menu/` — независимый экран меню, карточки и стили.
- `src/features/molecules/` — независимый экран молекул, canvas и бутылочки.
- `public/menu/images/` — карточки меню.
- `public/molecules/images/` — бутылочки.
- `public/home/images/icons/` — локальные WebP-иконки преимуществ (ico1–ico7).

## Авторизация: база данных и почта

Backend для регистрации и входа: Better Auth + Prisma + PostgreSQL. Подтверждение почты и восстановление пароля — SMTP. Не публикуйте реальные ключи и пароли в GitHub.

1. Скопируйте `.env.example` в `.env.local`. Заполните `DATABASE_URL`, `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET` (не менее 32 случайных символов), `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD` и `SMTP_FROM`.
2. `BETTER_AUTH_URL` должен соответствовать адресу сайта (локально `http://localhost:3000`, для production — публичный HTTPS-домен). Адрес отправителя `SMTP_FROM` должен быть разрешён SMTP-провайдером.
3. После создания базы данных примените миграции и запустите проект:

```cmd
npx prisma migrate deploy
npm run dev
```

4. Проверьте сценарии: регистрация → подтверждение почты → вход → `/account`; «Запомнить меня»; выход; восстановление по ссылке; запрет доступа к `/account` без сессии.

Если серверные переменные не настроены, `/api/auth/*` вернёт 503, а формы покажут ошибку. Успешная сборка не подтверждает подключение к реальной БД и отправку почты.

## Избранное и учётная запись

- Без входа избранное продолжает храниться локально в браузере (`petrolero-demo-favorites`).
- После подтверждённого входа гостевые товары автоматически и без дублирования объединяются с избранным аккаунта в PostgreSQL.
- Для авторизованного пользователя каталог и `/account/favorites` используют защищённый `/api/account/favorites`. Товары привязаны к ID пользователя, а не к браузеру; список загружается на любом устройстве после входа.
- Если сервер недоступен, избранное аккаунта не перезаписывается гостевым списком. Повторная загрузка доступна в интерфейсе.
- Не забудьте применить новую миграцию вместе с остальными: `npm run db:deploy`. Интеграционные тесты с временной PostgreSQL проверяют объединение, удаление, изоляцию покупателей и сохранение избранного.

## Демонстрационная корзина и оформление заказа

- `/catalog`: выбор товаров и локальная корзина. Кнопка **«Перейти к оформлению»** открывает `/checkout`.
- `/checkout`: адаптивная форма получателя и адреса, выбор сохранённого адреса для авторизованных, изменение количества и проверка позиций.
- Без входа доступны просмотр корзины и заполнение формы. Для сохранения тестовой записи нужен аккаунт; после входа покупатель возвращается на `/checkout`.
- После входа форма сохраняет только **демонстрационный заказ** через защищённый `/api/account/demo-orders`. Запись доступна в `/account/orders`, `/account/orders/[orderId]` и обзоре кабинета.
- Цена каждой позиции определяется на сервере по демонстрационному каталогу, а значения стоимости из браузера игнорируются. История и детали фильтруются по ID пользователя.
- **Нет реальной оплаты, расчёта доставки, резервирования, уведомлений продавцу или выполнения заказа.** Стоимость товаров не считается конечной суммой.
- После настройки БД нужна миграция: `npm run db:deploy`. Без БД, SMTP и авторизации сохранение недоступно; `/checkout` можно просматривать.
